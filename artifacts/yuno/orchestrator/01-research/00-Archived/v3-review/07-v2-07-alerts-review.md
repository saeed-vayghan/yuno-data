# Review · v2/07 Alert System & Metrics
**Verdict:** ⚠️ Pass with fixes. **Score:** 7/10. The split into a peer rule (for chronic problems) and a change rule (for drift) is right, and so is dbt owning data quality. But four rules have bugs you can build and test against: a robust z that divides by zero, a peer group that blames PSPs for country effects, dedupe that cannot give the same output on a rerun, and rules that read an unfinished week. The file also has more rules and jargon than a stretch goal needs.

## Debate highlights
⚡ **Kaveh:** Your outlier rule divides by zero. Two-thirds of the rows are exact matches, so the MAD is 0. Every cent of difference becomes "infinitely unusual".

🏛️ **Jamshid:** Fair. Robust z only makes sense on the flagged rows. We compute it there, and skip it when the MAD is still 0. The $50 rule does the real work anyway.

⚡ **Kaveh:** The peer rule compares PSP_B in Argentina with the whole world. If Argentina is bad for everyone, all four PSPs light up and PSP ops chases a country problem.

🏛️ **Jamshid:** Accepted. Peer = the other PSPs in the same country. That is also how P1 is planted, so the test now matches the data.

⚡ **Kaveh:** You promise "rerun gives the same output" and also NEW/ONGOING from the last run. You cannot have both.

🏛️ **Jamshid:** Then we drop the state file. We work out NEW/ONGOING/RESOLVED from this week vs last week inside one run. The output depends only on the data.

⚡ **Kaveh:** Eight rules, three states, Slack and a four-hop AWS path, for a 20-minute stretch goal. The brief says keep it simple.

🏛️ **Jamshid:** Six rules, one "worse" alert with WoW shown both ways as info, and a one-line AWS path. I keep the peer/change split, because that is the part that actually finds the chronic planted patterns.

## Must-fix list
1. **Robust z (F1):** compute it on flagged rows only, per PSP × country, and skip it when MAD = 0. Or use "`large` AND |Δ USD| > $50".
2. **Peer group (F2):** compare a PSP×country cell with the other PSPs in the same country, not the whole portfolio.
3. **Peer trigger (F3):** trailing 4 closed weeks. Fire on BH q < 0.05 AND a point gap ≥ 2 pp. Wilson CI is for display only.
4. **Dedupe (F4):** key = `rule_id|segment`. Work out NEW/ONGOING/RESOLVED inside one run from the current vs previous closed period, with no state file, so reruns are byte-identical.
5. **Closed weeks (F5):** evaluate weekly rules on the latest closed week (week end ≤ as_of − 7 days). Keep as_of = max data timestamp for pending aging.
6. **One "worse" rule (F6):** merge the WoW alert into the p-chart rule. Show the WoW change both ways (▲ worse / ▼ better) as INFO in the report and on the dashboard.
7. **Planted drift + fixtures (F7):** add one drift to `generator.yaml`. Add one firing and one silent test per rule.
8. **Outlier summary (F8):** one alert per run with the count, the $ total and the top segments. The rows go to the dashboard / `recon query --min-usd 50`.
9. **Smoke-run note (F9):** define n. State that at `--rows 500` every rule returns "insufficient data", and test it.
10. **Simplify (F10):** 6 rules. DQ = the dbt build fails. Slack stays optional. The AWS path is one line.
11. **Money leak (F11):** use a rate on the FX residual (auth-date FX), with thresholds in `thresholds.yaml` and distinct warn/crit severities. The report shows gross under, gross over and net.
12. **Pending aging (F12):** one aggregate alert per PSP × country. Ask 04 to put most pending rows in the last 7 days.
13. **Runner-up (F13):** add "alert rules as SQL in dbt" as the lean 🥈. Fix Grafana's con (its rules can be provisioned as code).
14. **Clarity (F14, F15):** split "engine choice" from "parts used". Add a plain one-line gloss per rule. Drop "EMF". Fix the stale EWMA reason.

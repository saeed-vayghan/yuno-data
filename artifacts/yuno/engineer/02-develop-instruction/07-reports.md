# 07 · Reports (`recon report`)

**Goal:** render `reports/FINDINGS.md` (≥ 4 evidence-backed findings) and `reports/RECOMMENDATIONS.md` (3–5 ranked actions with $) from data only. No hand-typed numbers.

**Time box:** part A FINDINGS 10 min · part B RECOMMENDATIONS 10 min
**Tag:** A **Core** · B **Stretch**

## Inputs
- File 06 outputs: `reports/findings.json`, `reports/analysis/*.csv`, `reports/figures/*`.
- (Optional) File 08 output `reports/alerts.jsonl` for the "Latest alerts" section.
- PLAYBOOK §7 finding format, §8 recommendations template · IMPLEMENTATION-PLAN S4.1, S5.2.

## Steps

### Part A · FINDINGS.md (Core)

1. **`report/render.py`:** Jinja2 `Environment(loader=FileSystemLoader(templates), undefined=StrictUndefined)`; filters `usd` (`$18,400`), `pct` (`17.1%`), `pts` (`+3.5 pts`), `q` (`q < 0.001` or `q = 0.012`), `ci` (`[16.2–18.1%]`).

2. **`templates/FINDINGS.md.j2`**, sections in this order:
   | # | Section | Content (all from data) |
   |---|---|---|
   | 1 | Summary (one screen) | rows, window, flag rate, gross under / over / net USD, "compared with $127k (estimate)", top 3 findings in one line each, worst PSP week last month |
   | 2 | Findings F1…Fn | fixed format (below) + figure under each |
   | 3 | Answers to the 5 brief questions | one short table per Q from `q1…q5` CSVs |
   | 4 | Model check | GLM odds ratios table (top terms), dropped terms if any |
   | 5 | Systematic vs random | signature table top 10 |
   | 6 | Cause labels vs truth | precision / recall per cause; "tip: ruled out (0 rows)" |
   | 7 | Sensitivity | flag rate at 1 / 2 / 3% |
   | 8 | Latest alerts | if `alerts.jsonl` exists: counts by severity + non-info rows |
   | 9 | Method notes | definitions link to README, "numbers are generated by `recon report`" |

3. **Finding format** (every F#):
   > **F1. {{ headline }}.** {{ rate | pct }} {{ metric }} on {{ segment }} (n = {{ n }}, 95% CI {{ ci | ci }}) vs {{ peer_rate | pct }} for peers — lift {{ lift }}×, {{ q | q }}. $ impact: {{ usd_quarter | usd }} per quarter ({{ share_of_loss | pct }} of loss; median loss {{ usd_median | usd }}). Likely cause: `{{ likely_cause }}`. Action: see {{ rec_ref }} (the R# from part B, or "RECOMMENDATIONS.md" before it exists).
   >
   > `![F1](figures/f1_….png)`
   Link figures **relative to `reports/`** so they render on GitHub.

4. **Wire `recon report`**: writes FINDINGS.md (and RECOMMENDATIONS.md once part B exists).

5. **Test "no hand-typed numbers"** (`tests/test_report.py`): strip every `{{ … }}` / `{% … %}` block from the templates; the remaining text may contain digits only in `F`/`R` labels, `95%` and `$127k`. Assert with a regex.

### Part B · RECOMMENDATIONS.md (Stretch)

6. **Action catalogue** in the template (text only, keyed by finding `key`):
   | Finding key | Action | Owner | Implementation |
   |---|---|---|---|
   | `psp_b_ar_peer` | Escalate PSP_B Argentina variance; renegotiate settlement terms | Payments ops | Weekly variance report to PSP_B; SLA clause with credit on excess |
   | `psp_d_rounding` | Get PSP_D to stop rounding CLP/COP cross-border settlements | Eng + PSP_D | Ticket with signature evidence; monitor `rounding_flag` share weekly |
   | `psp_c_fee_drift` | Dispute the new PSP_C per-transaction fee | Finance | Compare with contract (`psp_fees` = 0); claim back since month 3 |
   | `co_over_300_lag` | Settlement SLA for Colombia orders > $300 | PSP ops | Track lag p90; escalate > 7 days |
   | `cross_border` | Lock FX rate at authorization for cross-border | Finance | Yuno / PSP rate-lock option |
   | `partial_capture` / `fraud_hold` | Reconcile partial captures and holds to order changes | Ops | Join order events; auto-close explained rows |

7. **Ranking:** take findings that have a catalogue entry, rank by `saving = usd_quarter × reduction_pct` (reduction % stated per action in the template, e.g. 70% for a contract fix, 50% for a PSP escalation). Keep the top 3–5.

8. **Row format:** `Rank · Action · Evidence F# · Est. $ saving / quarter (method) · Owner · Implementation`, then one line "Assumption: saving = excess loss × {{ reduction }}%".

9. **Also write `reports/recommendations.json`** (same rows: `rank, action, evidence, usd_quarter, owner, implementation`) for `core.load_recommendations()`.

## Pitfalls
- **Hand-typed numbers** are the #1 review risk. `StrictUndefined` makes a missing key fail loudly instead of printing blank.
- **Do not cite non-significant findings** as F#; they go in a "Not significant" note.
- **$ reconciliation:** the cause Pareto in the summary must sum to the fct total (dbt test already checks the mart).
- **CFO 18% vs our ~14%:** the summary states "flagged ~14%, non-exact ~33%; synthetic data follows the brief's ranges". Do not claim to reproduce $127k.
- PNG may be missing in Docker/CI (kaleido); link `.png` if present, else `.html`.
- Recommendation savings are estimates; always print the reduction % used.
